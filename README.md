# ZKR Watch

A cinematic discovery platform for films and series. Browse a finite, curated catalogue, filter by
genre or era, open a title for cast, facts and an official trailer, and keep a watchlist that
persists in the browser.

**Live collection:** 121 titles — 69 films and 52 series, released between 1943 and 2026.

## Highlights

- **Cinematic home page** — rotating featured hero, trending, ranked top ten, genre mosaic,
  upcoming releases, hidden gems and world cinema.
- **Complete discovery** — browse all films or series, search across titles, people and genres,
  filter by genre, decade and year, and sort by popularity, rating, newest, oldest or A–Z.
- **Detail pages** — backdrop, poster, original title, rating, genres, synopsis, runtime or season
  count, cast, director/creator, production facts, official trailer, awards and similar titles.
- **Persistent watchlist** — add and remove titles, mark them watched, filter by status or type,
  track progress, and clear the list with a confirmation step. Stored under
  `zkr-watchlist:v1` in `localStorage` and synced across tabs.
- **Global search overlay** — `Ctrl K` / `⌘ K` (or `/`) from anywhere, with keyboard navigation
  and instant results.
- **Real assets only** — every title carries verified artwork and an official trailer, with clean
  fallbacks if an image or embed fails.
- **Responsive by design** — tested from 390 px mobile through wide desktop, with reduced-motion
  support and accessible controls.

## Stack

| Concern        | Choice                                                        |
| -------------- | ------------------------------------------------------------- |
| UI             | React 19, React Router 7                                      |
| Bundler        | esbuild (dev server, production build, code splitting)        |
| Styling        | Hand-written CSS with custom properties and responsive layers |
| Data           | Static JSON catalogue generated by a Node script              |
| State          | React context + `localStorage`                                |
| Runtime APIs   | None — the app makes no API calls at runtime                  |

There is **no Vite and no Create React App**. The toolchain is three small Node scripts and a
shared esbuild config.

## Getting started

Requires Node.js 20+.

```bash
npm install
npm run dev
```

Open <http://localhost:3000>.

| Command                 | What it does                                                     |
| ----------------------- | ---------------------------------------------------------------- |
| `npm run dev`           | Development server with live reload on port `3000`               |
| `npm start`             | Alias for `npm run dev`                                          |
| `npm run build`         | Production build into `dist/` with hashed assets                 |
| `npm run preview`       | Serve the production build on port `4000`                        |
| `npm run refresh:catalog` | Regenerate `src/data/catalog.json` from public sources         |

Set `PORT` to override the port, for example `PORT=8080 npm run dev`. If the requested port is
already taken, the dev and preview servers automatically use the next free port and print the URL
they chose, so a forgotten server never blocks startup. Development output goes to `.dev/`, which
keeps `npm run build` from disturbing a running dev server.

### Deployment

`npm run build` produces a fully static `dist/`. Deploy it to any static host, with a rewrite of
unknown paths to `index.html` so client-side routes resolve (for example `/title/tt0111161`).
No environment variables or secrets are required.

Development bundles are written to `.dev/` (also generated and git-ignored).

Content is deliberately separated from presentation: `src/data/catalog.json` is the source of
truth, `src/data/index.js` owns lookup/filter/sort logic, and pages/components only consume it.

## Data and provenance

Metadata is compiled ahead of time into a static JSON file, so browsing is fast and offline-safe.

| Data                              | Source                                         |
| --------------------------------- | ---------------------------------------------- |
| Titles, ratings, synopsis, genres | Cinemeta (IMDb metadata)                       |
| Series cast, seasons, episodes    | TVMaze                                         |
| Film cast and awards              | Wikipedia / Wikidata                           |
| Posters and backdrops             | Metahub image CDN (IMDb artwork)               |
| Trailers                          | Official YouTube uploads, verified via oEmbed  |

The refresh script:

1. Resolves each curated IMDb id through Cinemeta.
2. Enriches series with TVMaze and films with Wikipedia/Wikidata.
3. Searches YouTube, rejects sequels, spin-offs, reactions and fan uploads, and confirms the
   chosen video with the YouTube oEmbed endpoint.
4. Writes `src/data/catalog.json` and a report to `scripts/.cache/`.

No API keys are needed. Network responses are cached for seven days in `scripts/.cache/`, which is
git-ignored. To change the collection, edit `scripts/catalog-seed.mjs`, then run
`npm run refresh:catalog` and commit the regenerated JSON. Manual trailer overrides live in the
same seed file for cases where search cannot pick the right upload.

Artwork is loaded from `images.metahub.space`; the UI shows a typographic fallback card if an
image fails. Trailers use the privacy-enhanced `youtube-nocookie.com` embed and leave a link to
YouTube if embedding is unavailable.

This is a non-commercial portfolio project. Film and series metadata, artwork and trailers remain
the property of their respective rights holders.

## Accessibility and performance

- Semantic landmarks, skip link, labelled controls and visible focus states.
- Keyboard-operable search overlay, trailer dialog (Escape to close, focus management) and menus.
- Lazy-loaded route pages, lazy images below the fold and responsive artwork sizes.
- `prefers-reduced-motion` disables non-essential animation.
- No runtime API calls, no trackers, no accounts.

## Quality checks

Before shipping, the build was exercised in Chrome at 1440 px and 390 px:

- all navigation routes and the 404 page render correctly;
- genre, decade, year, type and sort filters update URL state and results;
- search overlay, search page and suggestion chips return correct matches;
- watchlist add/remove/watched states survive reload and sync across tabs;
- detail pages show real cast, facts, trailers and similar titles;
- images and YouTube thumbnails load, embeds use verified ids;
- layout has no horizontal overflow on mobile and the console is clean;
- `npm ls` contains only React, React DOM, React Router and esbuild — no Vite or CRA.
